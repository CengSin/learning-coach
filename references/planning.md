# 从目标到每日课程

## 首次执行

先判断项目是否已有可用计划。新项目只询问缺失的关键输入：可检验的目标、计划完成日或考试日、每周哪些天及各天可用时长、已有基础、用户资料的位置和必须保留的休息或不可用日期。已有项目先复用记录，不要求重复填写。官方日期尚未公布时，区分用户选定的内部准备截止日与待核实的正式日期；明确标注暂定依据。

根据资料目录和目标拆分阶段、模块及知识点。估计每部分的首次学习、练习、复习和缓冲用时，与截止前可用分钟数比较。估计不足时展示差额和可选择的取舍，不承诺一定达标。首次计划须保存整个期限的阶段及模块时间窗，并为每个计划日写一行简纲：日期、可用分钟、主线、可观察的当日成果和资料范围；远期简纲可粗，临近时细化。休息日也明确列出，不把计划当作已学习证据。

项目专有日期、每日简纲与修订依据写入 `data/course.json`，字段约定见 [state.md](state.md)。运行 `render.py build` 后，让用户能在计划页看到整体期限、阶段与模块时间窗、每日简纲和今天相对计划的位置。课程尚缺目标或期限时标为待规划，不能把空阶段表呈现为已排好的课程。

## 每日备课

开课前先取项目时区的当天日期，对照每日简纲、当前模块时间窗、最近真实作答和用户当次可用时间。若当日预算变化，先压缩复习或将低优先内容移后，保持当天主线。按简纲定位用户资料：Word／DOCX 使用可用的 documents 技能或相应读取工具；PDF 使用 PDF 技能、可靠本地提取或页图；其他格式采用能保留出处的读取方式。只读当天所需章节，核对关键图表与公式，标明资料版本和页码。`openai-docs` 用于 OpenAI 产品文档，不用于读取用户教材。

据此生成当日小纲：本日对应的阶段／模块与截止、能力目标、资料位置、时间分段、必要讲解、少量独立练习、验收点和顺延项。实际作答决定订正内容；一处局部错误不自动延长整个模块。复习在当日预算内设上限，逾期零散缺口进入复习队列，除非它阻断下一模块的必要前置。

## 调整计划

用户改变目标、截止日、可用时间或学习优先级时立即重排；缺课、连续几场偏离主线、阶段临近截止或周期复盘发现容量不足时也重排。先计算剩余学习日和分钟，区分已学、已做但待验证、尚未覆盖；展示旧计划与新计划的日期及内容差异、被移出的任务、对终点的影响。保留真实记录和原答案，不为匹配新计划改写过去。更新 `course.json` 的当前计划和修订记录，并把旧版计划存入项目 `history/`；生成视图后检查下一次小纲与当日计划一致。

阶段日期是推进和复盘检查点。到期时不能只因为仍有待复查项而无限停在原模块；须明确选择继续主线、压缩范围、调整里程碑或向用户说明目标与可用时间的缺口。当天课程不因页面重建、资料维护或自动重排而自行开课。
