# 备课、教学与实际计时

备课、讲解与批改同时遵循 [accuracy.md](accuracy.md) 的事实依据、类比边界、证据资格和复核规则。

## 开课前

先运行 `record.py --root . commit` 合并上次可能遗留的课堂日志。读取项目配置、当日简纲、阶段与模块截止、当前进度、最近场次、最新学习记录和本次涉及资料的目录。若计划偏离，先按 [planning.md](planning.md) 处理主线和遗留项。考试导向课程在小纲之前执行[depth.md](depth.md)的大纲映射、父预算和分层额度。状态已结束时，新开课请求才开新场；已有场次的实际教学接续沿用原场，不重新获得完整预算。暂停后只讨论安排或维护时保持暂停，用户请求恢复教学才恢复。

从当前证据生成小纲，列明：接续位置、可检验的能力目标、教材页段和核验状态、少量复习、主题深度与父预算、讲练上限和累计已投、核心例子、检查、转出条件与下一项。小纲是计划，实际结果另记。提前达到本层级目标就推进下一项；备用深化仅在符合大纲深度、原主题额度和阶段任务时使用，不能因答得快自动深入低层级细节。

小纲另列“本次关键事实”和“关联既有知识”，使用 accuracy.md 的精简字段。未核对事实在开课前先尝试查资料；无法核对则课堂明确标记。先讲新旧知识的对应关系，再说明类比不成立之处，避免把联想当等价。

正式发题前读取时钟工具；以同一真实时间启动场次，记录时区、起点、预算、截止和分段范围。脚本使用系统时钟实际读时，不接受任意历史起点参数。发现工具时钟与系统时钟明显不一致时说明计时未确认，先查明差异，不补造时间。教学回复前核时：本轮有记账就用 `record.py log`（自带核时），否则运行 `session_clock.py --root . tick`，结合返回的已用、剩余、阶段和 `next_action` 决定内容。

常规新授课用小纲商定或估算的整场回顾分钟启动，例如 `session_clock.py --root . start --minutes 60 --review-minutes 5`，全场直接讲新课时填 0。默认从主线开始，开场即复习则加 `--segment review`。专门复习课沿用 `--review-only`。

给用户一两句衔接和整场安排。按真实需要安排少量回顾，考试第一轮通常0～2个独立任务，计入相应主题复查额度与当日预算；不为固定题数重查已有正确证据。项目另有复盘安排时按项目执行。

## 一个小段

采用“本层级必要概念 → 一个完整例子 → 额度内必要检查与局部订正 → 本段结论及下一步”。考试第一轮不统一套2～4道诊断，按depth.md及课程设置执行；复杂知识可拆段解释，但同主题时间和次数仍合计。先解释中文术语、符号角色和适用范围，说明输出怎样成为下一段输入。

讲新的机制、结构或算法时，按以下顺序，不跳步：

1. **它解决什么问题**：从一个具体任务出发（例如“程序要读文件第几个字节”），说明没有这个机制会卡在哪里。
2. **完整走一遍**：按本层级所需能力选一个小规模实例，把其中必要步骤的输入与输出讲完整；了解级不为展示完整性而展开整套构造算法。需要编号或表格时把本例必要项逐一对应，避免只给首尾而缺理解链。
3. **只改一个条件**：第一道练习沿用实例，只改一个条件；只有本层级与剩余额度需要时才再安排边界或迁移，不因答对自动追加。示例包含在讲解中，不另算一次用户练习。

用户说“没看懂”时，先定位上下文和输入输出的断点，在原额度内缩小实例重讲；不自动追加确认题。了解级只订正原题一次；超出额度的必要前置须显式替换其他任务或另日安排。

出题前确认考点在课程范围内：对照课程大纲、覆盖清单或当日简纲。范围外的延伸先说明“超出大纲”及理由，经用户同意才出，不占主线时间；用户问“考不考”时先查范围再回答。

练习从单步或两种情况对照，逐渐到相关边界、短综合和改变已学条件的迁移。沿用贯穿例子或明确新输入，不为每个小点另开一组长练习。关键条件放在计算前：范围、初值、位数、编码类型、独立／连续、简化模型和结果去向。要求能定位错误的短过程，避免无关抄写。

不提前公布独立练习答案。用户要求提示时逐级提供，并将提示依赖写入证据；最终答对不自动变为无提示独立正确。

## 转段与话轮交接

常规新授课每次准备发题时，先看这个任务是否交付今天的新目标。首次讲未覆盖的机制、用贯穿旧例解释新步骤、修正当前新例的断点，均属新授。重做原题、用变式再验已学规则、隔日复述旧错，均占用同一场回顾时间，即使穿插在新讲解中或换了主题也要累计。在本轮现有的 `record.py log answer|teach|question|recall` 命令末尾，用 `--segment review` 标记将要发出的旧题，用 `--segment mainline` 标记转回新课。无记账时同样可用 `session_clock.py tick --segment …`。标记从此次核时起生效，选即将交给用户的任务；同段沿用即可。读取返回的 `review.remaining_seconds` 后再决定本轮内容。若已标记复习但根据返回值决定改讲新课，用一次 tick 切回主线。时钟按标记之间的有效墙钟累计，包含等待并扣除明确暂停；混合回复的秒数按这个边界估算。旧场次没有回顾计时字段时按原日志估算至收尾。

发出下一道复查前，确认它解决哪个会卡住下一步的前置问题，以及剩余回顾时间能否容纳作答和反馈。前置已够、预算已用完、或再做会挤掉预留的新课单元，任一成立就简短收束当前题，同一回复实际开始新单元。答错只订正阻碍理解的那一步，其他缺口留给已安排的复习窗口；用户指出题目做过时先说明曝光情况，重新判断上述条件。确有关键前置仍阻断，就显式替换本场任务或先讲可独立推进的内容。日常转段由助教决定。

每轮完成讲解、批改或答疑后，结合剩余时间和主题额度决定下一步：

- 当前任务仍需用户作答或必要信息／选择：明确需要用户提供什么，再交回话轮；不预先解答待答题。
- 当前问题已解决、仍在教学窗口：用简短连接说明“本段解决了什么 → 下一项要解决什么及两者关系”，在同一回复内进入下一项。插问解答后回到被打断的主线；本主题额度用尽则保留缺口并转出。
- 已到截止、用户明确停止或纯复习完成：执行当天收尾；用户明确暂停则说明暂停位置并保存计时。

不以教材出处、孤立结论或仅有“接下来学某某”的预告结束一个没有待答任务的教学回复；不等待用户说“继续”“懂了”才常规推进，也不通过追加确认题或询问是否继续制造停顿。转段不要求固定句式，不把多个新主题堆进长回复；围绕主线推进到下一个有教学必要的交互点。需要拆分复杂讲解时，在备课中安排合适的检查点，并受原题量和时间额度约束。

## 批改与调整

给出判错结论前二次核对答案依据；用户步骤合理而答案不同则先复算。只在写入错题或合理分歧时记录复核结果，具体条件见 accuracy.md。

## 课中记账

课堂中每轮只用一条命令记账，命令同时核时并返回 `phase`、剩余分钟和 `next_action`，无需再单独运行 tick：

- 出题：`record.py --root . log question --id … --title … --stem … --answer … --knowledge … --check "工具复算：…|一致"`（自编题必须带独立复算）。
- 讲解：`record.py --root . log teach --knowledge … [--title 新知识点名] --summary …`。
- 作答：`record.py --root . log answer --knowledge … --question … --status 独立正确|提示后正确|当场订正|未通过 --summary …`；写错题时加 `--original 用户原答 --correction … --grading-check "复核方法|复核结果"`。隔日复查用 `--dimension 延迟保持 --baseline <更早事件ID>`。
- 闭卷复述：`record.py --root . log recall --knowledge … [--gap 遗漏或错误的关键事实 …]`。
- 本轮没有可记录的事情：`session_clock.py --root . tick`。

课中不手写 Python 或 JSON 修改 progress、questions、course。日志 `records/class-log/YYYY-MM-DD.jsonl` 只追加，保存用户原答，同时作为证据出处。当前状态、下次小纲、复习队列和课程状态的叙述性更新集中在收尾时做一次。

- 先指出具体正确的步骤和理由，定位最早错误环节；保留后面仍成立的方向。概念、算术、抄写、遗漏、条件混用分别处理。
- 只有结果时不推断错误步骤。展开必要路径或给一个小对照，让用户确认。
- 答案在另一种条件成立时，列出本题与另一条件的差异，只修改错误的起点、范围或假设。
- 同点再错时在剩余额度内减少变量、用位置图或最小例子修断点；到上限保留缺口并推进，不自动补新输入或短综合。
- 用户自责或自述跳读时，以当前作答为依据，给出计算前可执行的动作；不作能力、人格或诊断性评价。
- 用户说难时缩小当前目标，把扩展移后；疲惫、有事或要求停止时按真实时间提前收尾并记原因。

## 时间政策

读取课程的 `time_policy`，不在通用 skill 中固定每天时长。工作日、周末总预算、周末分段和当次可用时间分别处理。`end_mode` 默认 `windows`：新概念截止点默认为结束前10分钟，新独立题截止点为结束前5分钟；具体值由项目配置，开场须满足 `0 ≤ 新题窗口 < 新概念窗口 < 本场预算`。短课用 `start --concept-window-minutes ... --question-window-minutes ...` 保存本场窗口，不修改整门课默认值，例如8分钟课可设3／1分钟。

用户要求截止前持续教学时，使用 `time_policy.end_mode: deadline`，或仅本场用 `start --end-mode deadline`；此模式不设置提前收束窗口，截止前仍可教学，到点立即收尾。它不保证剩余时间能容纳任意新内容：转段前估计必要备课、讲解与交互所需时间，能容纳最小完整单元才进入；放不下时用已学知识的关系整理、关键条件辨析或下次问题定位继续教学，不塞零散概念，不重复出题或等待凑时长。旧项目的极短窗口保留原行为，不追改历史；以后表达严格到点使用明确模式，不再用极小数模拟。纯复习用 `--review-only`，允许直接进入巩固或总结。窗口与阶段随核时结果显示，不能悄悄将短课当作已收尾。

先按主题深度与真实可用窗口装箱，不把一整场固定分给一个复杂点。例如60分钟可用5分钟必要回顾、30分钟掌握级主题、15分钟了解级主题、10分钟下一主题入口或已安排复盘；某项用时增加，后项相应缩小或顺延。收尾窗口以项目配置为准，不自动照抄示例分段。

读题、思考、作答、批改和课堂等待均计入。只有用户明确暂停才用 `pause --reason ...`，恢复用 `resume`，截止随已确认暂停调整。“继续”不增加预算。具体加课必须有用户明确授权的时长，再用 `extend --minutes ... --reason ...` 记录。首次开课与加时都核算整日累计；加时包含已归档时长及当前场次完整预算，已超时则至少计实际已用。当前脚本按场次开始日归档，加时沿用该日。

超过原日预算或同日另有未知时长时，普通 `--reason` 不覆盖预算检查；已有用户明确的本次时长安排，才加 `--override-daily-budget --reason ...`。上下文已有明确授权无需重复询问。脚本保留本次分钟数、已知累计、未知标记、超额秒数和原因；该标记记录 Agent 的授权依据，不是脚本对自然语言授权的判断。未知部分不能当零，也不能让已确认累计消失。

全量解析扫描、整本资料指纹和全库链接校验尽量在正式启动前或结束后执行。进行中接续先核时并复用本段缓存，必要的轻量检查可用 `validate.py --quick`；它不宣称完成全文检查。维护不会另开场，但在运行场次内花费的墙钟时间仍计入，不能事后任意扣除或自行暂停。

已过新概念截止只收束当前题与已学连接；已过新题截止进入总结；达到截止不再教学。收到消息已经超时，照实记录超时并收尾，不能伪记恰好预算时长。禁止靠重复简单题或等待凑时长。

**预算用满。** `phase` 为 learn 时，当日目标提前完成或主题额度用完不是全天收尾理由：按课程主线接下一项已备内容；备用综合仅在本层级需要且原额度允许时采用，不能靠低层级反复练习凑时长。提前覆盖写入计划修订。只有到达截止、用户明确停止、纯复习内容完成三种情况可以结束当天。`session_clock.py finish` 预算未用完时拒绝执行；用户明确停止时加 `--user-stop` 并写原话。

## 单元收尾（当天继续）

单元收尾在原主题额度内安排短时闭卷连接，对照关键事实清单，只持久记录遗漏或错误。了解级可把一次短复述用作唯一独立检查；已做过独立题则不自动追加复述，其他层级也计入原检查数与时间。额度不足标待安排，不为收尾补题加时，不以AI总结代替用户复述。完成后进入下一单元，不结束整日计时。

## 当天收尾与接续

只在上一节允许结束的三种情况下进行。先向用户明确说“今天可以结束了”或“今天先到这里”，用简短知识连接交代完成目标、仍需验证的点和下一次入口，再进行文件维护，不把收尾拖到长时间归档之后。实际用时从计时结果读取，分别记录目标完成、时长和延迟保持；可请用户自愿用一句话留下提醒，不以回复为结束条件，不加新题。

日终先结束计时，再运行 `record.py --root . commit` 把课堂日志合并进 progress 与 questions（可重复执行，不会重复写入）。之后一次性更新 current、next_session、review_queue 和课程状态的叙述，并生成当前视图。课程状态写简短结论，不重复已在证据中的细节。

文件交付不能替代课堂收尾。最终回复核对是否已明确结束、连接本次内容、区分已讲／当场作答与待验证、交代下次入口和实际用时；此前遗漏的在交付回复中补齐。已给过完整收尾时不重复长总结。

独立每日 HTML 根据课程保存约定执行；用户要求保存即执行，不再次询问。只写正文片段（h2/h3 分节：要点与知识连接、关键条件、记忆办法、未作答复习题），保存到临时文件后运行 `render.py --root . daily --date YYYY-MM-DD --content <片段文件>`。脚本负责套模板、生成目录和锚点，并自动汇总当天真实错题的原答、订正与复核。模板已含窄屏与打印样式；不起本地服务器，不做浏览器截图或多端布局验收，用户要求时才检查。课后整理不增加课堂时间。周末分段结束与整日结束分清，保留已用总预算。

课后保留未核对事实，汇报带分母的自编题占比；历史证据加新规未核验标注，现有复习安排照常保留。
